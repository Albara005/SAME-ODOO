# النشر على Railway

المنصة كلها في حاوية واحدة: الخادم (FastAPI) يقدّم الواجهة المبنية، والعامل الخلفي يعمل بجانبه، ومعها قاعدة PostgreSQL من Railway.
يبني Railway الحاوية من الملف `Dockerfile` في جذر المستودع تلقائياً، ويجهّز `novara/serve.py` قاعدة البيانات عند كل تشغيل:

- ينشئ دور التشغيل `novara_app`، وهو دور ليس مالكاً ولا مشرفاً، فتنطبق عليه عزل الصفوف (RLS) دائماً.
- يطبّق الترحيلات بحساب المسؤول.
- يشغّل الخادم بدور التشغيل.

## الخطوات

1. **المشروع:** في Railway اختر **New Project ← Deploy from GitHub repo**، ثم المستودع `SAME-ODOO`.
   - اختر الفرع الذي فيه هذا العمل: `main` بعد دمج الـ PR، أو `claude/amazing-mccarthy-3uv0tr` قبله.
   - تجده من **Settings ← Source ← Branch**.
2. **قاعدة البيانات:** من **+ New ← Database ← PostgreSQL**.
3. **ربط القاعدة بالخدمة:** افتح خدمة التطبيق ثم **Variables ← New Variable** وأضف:

   | الاسم | القيمة |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `PORT` | `8000` |

   القيمة إشارة إلى متغير خدمة PostgreSQL. اكتبها كما هي، أو اخترها من **Add Reference**. إن كان اسم خدمة القاعدة غير `Postgres` فاستعمل اسمها.
4. **عنوان الموقع:** من **Settings ← Networking ← Generate Domain**، والمنفذ `8000` (كالمتغير `PORT` أعلاه).
5. **حفظ الملفات المرفوعة (اختياري ومستحسن):** أضف **Volume** للخدمة مساره `/data`، فتبقى المرفقات والمستندات بعد كل نشر جديد. بدونه تضيع عند إعادة النشر.
6. افتح العنوان، ثم أنشئ حساباً، ثم أنشئ مؤسسة.

يستغرق البناء الأول بضع دقائق. وتظهر في **Deploy Logs** سطور `applied migration` (52 في أول مرة)، ثم `Uvicorn running`.

## متغيرات إضافية

| المتغير | متى تحتاجه |
|---|---|
| `NOVARA_JWT_SECRET` و`NOVARA_ENCRYPTION_KEY` | للاستعمال الحقيقي: نص عشوائي من 48 حرفاً أو أكثر لكل منهما. ضعهما قبل أول تشغيل. إن لم تضعهما تولّدهما المنصة مرة واحدة وتحفظهما في القاعدة في مخطط لا يقرؤه دور التشغيل، ويظهر تحذير في السجل. هذا يكفي للتجربة. وتغييرهما لاحقاً يُخرج الجميع من حساباتهم، ويُبطل الأسرار المحفوظة مشفّرة (التحقق بخطوتين، مفاتيح بوابات الدفع). |
| `ANTHROPIC_API_KEY` | ليعمل المساعد الذكي ومُنشئ التطبيقات ووكيل التصميم. |
| `NOVARA_SMTP_HOST` و`NOVARA_SMTP_PORT` و`NOVARA_SMTP_USER` و`NOVARA_SMTP_PASSWORD` و`NOVARA_MAIL_FROM` | لإرسال البريد: تأكيد البريد، واستعادة كلمة المرور، والدعوات. بدونها تُكتب الرسائل في السجل، ويظل الدخول يعمل. |
| `NOVARA_APP_BASE_URL` | إن ربطت نطاقك الخاص: `https://erp.example.com`. بدونه يُستعمل نطاق Railway. |
| `NOVARA_STORAGE_BACKEND=s3` ومتغيرات `NOVARA_S3_*` | لحفظ الملفات في S3 أو R2 بدل القرص (`docs/phase-1-foundation.md`). |

## ما يجب معرفته

- **النسخ الاحتياطي:** Railway يحفظ نسخاً لقاعدته حسب خطتك. أما النسخ المشفّرة الموصوفة في `infrastructure/backup` فتحتاج تشغيلها كمهمة مجدولة.
- **عناوين الزوار:** حدود المحاولات لكل عنوان تعتمد على عنوان الزائر الذي يمرّره وكيل Railway. لذلك تثق الحاوية بترويسات التمرير (`--forwarded-allow-ips '*'`)، فلا يصلها شيء إلا عبر ذلك الوكيل.
- **نشر في الإنتاج الكامل:** خلف nginx بإعداداته (`infrastructure/deployment/nginx.conf`) وبدورَي قاعدة منفصلين (`infrastructure/deployment/postgres-roles.sql`). المفتاح `NOVARA_DATABASE_URL` إذا وُضع يتجاوز التجهيز التلقائي كله.
- **فحوص المتصفح في استوديو التطبيقات:** متوقفة في هذه الحاوية لأنها لا تتضمن Chromium.
- **التجربة محلياً بالحاوية نفسها:**

  ```bash
  docker build -t novara .
  docker run -p 8000:8000 -e DATABASE_URL=postgresql://postgres:secret@host.docker.internal:5432/novara novara
  ```
