# NOVARA: المخطط الشامل للمنصة

> **NOVARA اسم مؤقت.** هذا الملف ملخص منظم للمخطط المعتمد، ويُستخدم مرجعًا لقرارات المشروع.
> عند تعارضه مع الكود، الكود والاختبارات هي ما يصف الحالة الفعلية، وهذا الملف يصف الاتجاه.

## الرؤية

منصة واحدة تمكّن الشركات والأفراد من إدارة أعمالهم، وبناء تطبيقاتهم، وتصميم هوياتهم، وإنشاء وكلاء ذكاء اصطناعي، وتشغيل أعمالهم الرقمية من مكان واحد.
الهدف ليس نسخة من Odoo، بل منصة تجمع قوة أنظمة الأعمال مع بناء التطبيقات والذكاء الاصطناعي والتصميم.

| الوحدة | الوظيفة |
|---|---|
| Business Suite | المبيعات، المحاسبة، المخزون، الموارد البشرية، المشاريع، المتجر |
| AI App Studio | بناء تطبيقات حقيقية قابلة للتشغيل والاختبار والتصدير |
| Agent Platform | وكلاء مخصصون بأدوات وصلاحيات وميزانيات محددة |
| Creative Studio | الهوية البصرية، الشعارات، أنظمة الألوان (Design Tokens) |
| Automation | محرك سير عمل موثوق (Trigger → Conditions → Actions → Approvals) |
| Cloud & Deployment | الاستضافة والنشر، مع قرارات صريحة لإنشاء الموارد |

## المبادئ الحاكمة

1. **نظام واحد وبيانات مترابطة:** العميل والمنتج والفاتورة لا تُعرَّف مرتين.
2. **الذكاء الاصطناعي ينفّذ عملًا حقيقيًا قابلًا للتحقق:** ملفات وكود واختبارات، لا واجهات شكلية.
3. **وحدات قابلة للإضافة دون كسر القديم.**
4. **الأمان من البداية:** الصلاحيات والعزل والنسخ الاحتياطي والتدقيق جزء من التصميم.
5. **لا إنشاء لسيرفرات أو تغيير لاستضافة عميل دون موافقة صريحة.**
6. **منتج أصغر موثوق أفضل من وحدات كثيرة غير مكتملة.**

## البنية المنطقية

```
واجهة المنصة (لوحة التحكم، التطبيقات، المحرر، المساعد)
        │
Control Plane: الدخول، المؤسسات، الصلاحيات، الاشتراكات، حدود الاستخدام، التدقيق
        │
Business Platform │ AI Platform │ App Platform │ Creative Platform
        │
Data Plane: PostgreSQL، تخزين الكائنات، الطوابير، البحث، السجلات
        │
Execution Plane: عمّال المهام، بيئات تشغيل معزولة، الخدمات المنشورة
```

الواجهة لا تتصل مباشرة بقاعدة البيانات ولا بخوادم تشغيل الكود. كل وصول يمر عبر خدمات تتحقق من الصلاحيات.

## القرارات الهندسية المعتمدة مبدئيًا

| القرار | الاختيار | الحالة |
|---|---|---|
| الاستضافة | قاعدة مشتركة مع عزل قوي على مستوى المؤسسة، وإمكانية نقل مؤسسة إلى قاعدة أو بيئة مستقلة | مطبّق (`hosting_mode`) |
| العزل | فلترة تلقائية في طبقة الوصول للبيانات + Row-Level Security في PostgreSQL | مطبّق ومختبر |
| الخلفية | Python + FastAPI | مطبّق |
| البيانات | PostgreSQL، وSQLite للتطوير والاختبار السريع | مطبّق |
| الملفات | تخزين كائنات متوافق مع S3، مع واجهة محلية للتطوير | الواجهة المحلية مطبّقة، وS3 لاحقًا |
| المال | المبالغ أعداد صحيحة بأصغر وحدة للعملة، والكميات أرقام عشرية دقيقة | مطبّق |
| المحاسبة | قيود مزدوجة متوازنة، للإضافة فقط، وتصحيح بالعكس، ومفروضة في القاعدة أيضًا | مطبّق |
| المخزون | جرد مستمر بمتوسط التكلفة المرجّح لكل مستودع | مطبّق |
| الواجهة | TypeScript + React (Next.js عند الملاءمة) | لم يبدأ |
| الكود المولّد | يُعامل كغير موثوق: بيئات معزولة (MicroVM أو ما يعادله)، ونشر الإنتاج قرار منفصل | المرحلة 4 |
| البنية | تطبيق خلفي واحد بوحدات واضحة، وفصل الخدمات عند الحاجة الفعلية فقط | مطبّق |

## مراحل التنفيذ ومعايير القبول

| المرحلة | المحتوى | معيار الإنجاز |
|---|---|---|
| **1. الأساس** | الحسابات، المؤسسات، الصلاحيات، قاعدة البيانات، الملفات، التدقيق، النسخ الاحتياطي، لوحة أولية | إنشاء مؤسسة، إضافة مستخدمين، وتقييد الوصول لبيانات كل مؤسسة **والتحقق باختبارات** |
| 2. أول منتج تجاري | العملاء، المنتجات، عروض الأسعار، المخزون الأساسي، الفواتير، قيود مزدوجة، تقارير، استيراد/تصدير | شركة تجريبية تتم دورة بيع كاملة ويُتحقق من أثرها على المخزون والفاتورة والحسابات |
| 3. المساعد الذكي | أسئلة على البيانات، تلخيص، مسودات، إجراءات محدودة بأذونات، سجل أفعال | مهام اختبارية صحيحة وقابلة للتتبع دون تجاوز الصلاحيات |
| 4. AI App Studio | قوالب، توليد كود، بناء معزول، معاينة، اختبارات، إصدارات، نشر بموافقة | تطبيقات من نطاق محدد تُختبر وتُنشر بأمان |
| 5. الوكلاء والأتمتة | Agent Builder، الأدوات والمعرفة، حدود التكلفة، الإصدارات، محرك الأتمتة | وكيل يُعد ويُختبر ويُنشر بصلاحيات وحدود واضحة |
| 6. التصميم والتوسع | Creative Studio، مزيد من وحدات ERP، المتجر، الموارد البشرية، التكاملات، الاستضافة الخاصة | ميزات جديدة دون إضعاف الأمان أو الاستقرار |

لا توجد مدد زمنية قطعية قبل معرفة حجم الفريق والميزانية.

## قواعد غير قابلة للتفاوض

- إخفاء زر في الواجهة ليس حماية. الصلاحيات تُفرض في الخادم في كل عملية حساسة.
- لا يعتمد العزل على تذكّر المطور إضافة شرط المؤسسة في كل استعلام.
- لا تُخزَّن كلمات المرور أو مفاتيح API كنص عادي، ولا أسرار في Git.
- سجل التدقيق للإضافة فقط.
- المحاسبة دفتر أستاذ مزدوج القيد بقيود متوازنة، ومراجعة محاسب مختص قبل الاستخدام المالي الفعلي.
- العمليات الحساسة تستخدم مفاتيح منع التكرار (idempotency) حتى لا تُنشأ فاتورة مرتين.
- تعليمات النموذج ليست وسيلة أمان. صلاحيات الوكيل تُفرض خارج النموذج، والمحتوى المقروء من المستندات بيانات وليس أوامر.
- لا نشر آلي غير مشروط لكود مولّد. النسخة الاحتياطية التي لم تُستعَد فعليًا لا تُعتبر نسخة احتياطية.
- العميل يستطيع تصدير بياناته ومشاريعه.

## ما نؤجله عمدًا

عشرات التطبيقات قبل ثبات النواة، سوق إضافات عام، محاسبة لكل البلدان، سيرفر دائم لكل وكيل،
عشرات الخدمات الموزعة، 3D متقدم بلا حاجة، توليد تطبيقات بلا حدود أو قوالب، ووعود بأن الذكاء الاصطناعي يبني أي نظام دون تدخل بشري.
