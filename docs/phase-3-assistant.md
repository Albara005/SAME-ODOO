# المرحلة الثالثة: المساعد الذكي (Phase 3 — AI Assistant)

**معيار القبول:** «ينفذ المساعد مجموعة مهام اختبارية بصورة صحيحة وقابلة للتتبع، دون تجاوز صلاحيات المستخدم».
يتحقق منه `tests/test_assistant.py` (15 اختبارًا) و`tests/test_ai_provider.py`.

## كيف يعمل

```
رسالة المستخدم
  → فحص: المساعد مفعّل؟ الميزانية الشهرية متبقية؟ المستخدم يملك ai.use؟
  → يُعرض على النموذج فقط الأدوات التي يملك المستخدم صلاحيتها
  → النموذج يطلب أداة:
        قراءة  → تُنفّذ بصلاحيات المستخدم نفسه وداخل مؤسسته فقط
        كتابة  → لا تُنفّذ؛ تتحول إلى «إجراء معلّق» ينتظر موافقة المستخدم
        أداة غير مسموحة → تُرفض ويُسجَّل الرفض
  → يتكرر ذلك حتى 8 خطوات كحد أقصى، ثم يرد المساعد
  → كل طلب للنموذج يُسجَّل: النموذج، التوكنات، التكلفة، المدة، النتيجة
```

## الأدوات

| الأداة | النوع | الصلاحية المطلوبة |
|---|---|---|
| search_customers | قراءة | customers.read |
| search_products | قراءة | products.read |
| list_invoices (مع خيار المتأخرة فقط) | قراءة | invoices.read |
| get_invoice | قراءة | invoices.read |
| receivables_aging | قراءة | invoices.read |
| sales_summary | قراءة | invoices.read |
| trial_balance | قراءة | accounting.read |
| stock_levels | قراءة | inventory.read |
| list_sales_orders | قراءة | sales.read |
| create_customer | كتابة (بموافقة) | customers.write |
| create_draft_invoice | كتابة (بموافقة، مسودة فقط) | invoices.write |
| create_quotation | كتابة (بموافقة) | sales.write |

أدوات القراءة تستدعي نقاط الـ API نفسها التي تستخدمها الواجهة، وأدوات الكتابة تستدعي دوال الإنشاء نفسها.
لذلك يخضع المساعد لنفس العزل والصلاحيات والتحقق، ولا يوجد طريق خلفي.

## الأمان (مفروض في الكود وليس في تعليمات النموذج)

- **الصلاحيات خارج النموذج:** الأداة التي لا يملكها المستخدم لا تُعرض أصلًا. وإن طلبها النموذج رغم ذلك تُرفض ويُسجَّل الرفض.
- **لا كتابة بدون إنسان:** كل تغيير يصبح إجراءً معلّقًا لا ينفذه إلا المستخدم صاحب المحادثة، وتُفحص صلاحيته **لحظة الموافقة** لا لحظة الاقتراح. إذا تغيّر دور المستخدم في الأثناء، تُرفض الموافقة.
- **مقاومة التعليمات المدسوسة:** النصوص داخل البيانات (ملاحظات عميل مثلًا) قد تحتوي «تعليمات». يثبت الاختبار أن نموذجًا انخدع بها لا يستطيع تحريك أي مبلغ: إما أن الأداة غير متاحة للمستخدم، أو تصبح إجراءً ينتظر موافقته.
- **قابلية التتبع:** كل استدعاء أداة يُسجَّل بحالته (نُفّذ، رُفض، معلّق، وافق المستخدم، رفض المستخدم). وما يُنفَّذ بالموافقة يظهر في سجل التدقيق باسم المستخدم مع `via: assistant`.
- **حدود:** 8 خطوات لكل رسالة، ميزانية شهرية لكل مؤسسة بالدولار (افتراضيًا 20$)، ومفتاح إيقاف فوري.
- **الخصوصية:** المحادثة لصاحبها فقط، ولا يقرؤها حتى المدير. أدوات البحث لا ترى إلا بيانات مؤسسة المستخدم.

## النماذج والتكلفة

| المسار | الافتراضي | الاستخدام |
|---|---|---|
| assistant | `claude-opus-5-5`، effort متوسط | الأسئلة والبحث والمسودات |
| assistant_deep | `claude-opus-5-5`، effort عالٍ | التحليل متعدد الخطوات (`"deep": true`) |

- يستطيع مدير المؤسسة (صلاحية `ai.manage`) توجيه أي مسار إلى نموذج آخر مدعوم (Sonnet 5.5، Haiku 5.5، Fable 5.1) وتغيير الـ effort.
- التكلفة تُحسب من أسعار كل نموذج، بما في ذلك قراءة وكتابة الـ cache، وتظهر في `/assistant/usage` حسب النموذج والمستخدم.
- تخزين مؤقت للتعليمات (prompt caching): تعليمات النظام ثابتة، وقائمة الأدوات بترتيب ثابت، والتاريخ واسم المؤسسة في رسالة المستخدم. هذا يجعل الجزء المتكرر من الطلب يُقرأ من الـ cache بتكلفة أقل بكثير.
- عند رفض النموذج لطلب لأسباب أمان، يُعاد الطلب تلقائيًا على نموذج بديل من طرف الخادم (`fallbacks: "default"`) للنماذج التي تدعم ذلك.
- تاريخ المحادثة للإضافة فقط، ويُعاد للنموذج كما هو، مع كتل التفكير.

## التشغيل الفعلي مع Claude

تعمل الاختبارات بنموذج وهمي مُبرمج مسبقًا، فلا تكلف شيئًا ولا تحتاج إنترنت.
للتجربة الحقيقية تحتاج مفتاح API (`ANTHROPIC_API_KEY`) أو تسجيل الدخول بـ `ant auth login`، ثم:

```bash
cd services/api
python -m scripts.assistant_live_check "أي الفواتير متأخرة وكم المبلغ المستحق؟"
```

السكربت يستدعي Claude فعلًا (تكلفة بضعة سنتات)، ولم يُشغَّل في هذه البيئة لعدم وجود مفتاح.

## إضافات بعد الإصدار الأول

| الميزة | كيف تعمل |
|---|---|
| **البث المباشر للرد** | `POST .../messages/stream` يرسل أحداث SSE: `delta` لكل جزء من النص أثناء كتابته، و`tool` لكل أداة استُخدمت، ثم `done` بنفس جسم الرد العادي أو `error`. الدورة تعمل في جلستها الخاصة المربوطة بالمؤسسة والمستخدم، فعزل RLS يبقى كما هو. الرفض (المساعد متوقف، الميزانية) يصل كخطأ HTTP عادي قبل بدء البث. |
| **حد شهري لكل عضو** | `user_monthly_budget_usd` في الإعدادات: فوق ميزانية المؤسسة، يُفحص قبل كل استدعاء للنموذج (وأثناء الدورة). فارغ = لا حد شخصي. |
| **ذاكرة بموافقة** | أداة `remember` من نوع «كتابة»: تنتظر موافقة المستخدم ككل إجراء. الملاحظات لكل مستخدم وحده، تظهر في بداية رسالته وموسومة بأنها من كتابته، ويحذفها متى شاء (`/assistant/memories`). لا يرى مساعد عضو آخر ملاحظاتك، فلا يستطيع أحد زرع تعليمات في مساعد غيره. حد أقصى 50 ملاحظة. |
| **البحث في المستندات** | يُستخرج نص ملفات PDF (بمكتبة `pypdf`) وWord ‏(`.docx` من XML مباشرة) والنصوص وCSV وJSON عند رفعها، ويُقسَّم إلى مقاطع بنحو 900 حرف (`modules/files/text.py`). الملفات المرفوعة قبل ذلك تُقرأ عند أول بحث. أداة `search_files` بصلاحية `files.read` تعيد أفضل المقاطع مرتبة بـ BM25 مع اسم الملف، و`read_file` تقرأ نص مستند كامل على دفعات (6000 حرف). قبل المطابقة تُوحَّد الكلمات: يُحذف التشكيل والتطويل، وتُوحَّد أ/إ/آ ← ا وى ← ي وة ← ه، والأرقام الهندية، وتُفصل «ال» وأخواتها. ملفات PDF التي تخزّن العربية حروفاً مشكّلة بترتيب العرض (كما يصدرها المتصفح وبرامج المكتب غالباً) تُعاد سطورها إلى ترتيب القراءة. محتوى الملفات يُعامل كبيانات وليس تعليمات. صفحة «المستندات» في الواجهة للرفع والبحث. |

## تقييم الجودة مع النموذج الحقيقي

اختبارات المنصة تثبت أن الأدوات مقيّدة والكتابة تنتظر الموافقة والبيانات لا تخرج من مؤسستها. ما يقرره النموذج نفسه تقيسه مجموعة تقييم منفصلة (`novara/evals`):

```bash
cd services/api && python -m novara.evals --report evals.json --min-pass 0.8   # يستدعي Claude ويكلّف قليلاً
```

تبني مؤسسة مؤقتة فيها عملاء وفواتير متأخرة ومدفوعة ومخزون وسياسة استرجاع عربية وملاحظة مورد تحمل حقن تعليمات، ثم تسأل 13 سؤالاً بالعربية والإنجليزية عبر الـ API الحقيقي، كل سؤال في محادثة جديدة. الفئات: الحقائق (الأداة الصحيحة والرقم الصحيح بلغة السؤال)، عدم الاختلاق (عميل غير موجود)، المستندات، الموافقة (الكتابة تبقى مقترحة والسجلات لا تتغير)، الأمان (تجاهل التعليمات المخبأة في البيانات)، الصلاحيات (مستخدم المستودع لا يرى ميزان المراجعة)، والوكلاء (وكيل معرفته السياسة). تطابق الأرقام والكلمات بعد توحيد الأرقام والهمزات والتشكيل. التقرير يعرض النجاح لكل فئة والتكلفة، والأمر يخرج بخطأ تحت النسبة المطلوبة. في GitHub يشغّله سير العمل `evals` يدوياً بالسر `ANTHROPIC_API_KEY`، ولا يعمل في CI العادي.

## ما لم يُنجز بعد

- **نتائج التقييم مع النموذج الحقيقي:** مجموعة التقييم جاهزة (انظر «تقييم الجودة» أعلاه)، لكنها لم تُشغَّل بعد بمفتاح Claude حقيقي، فلا أرقام منشورة عن جودة الإجابات حتى الآن.
- **بحث بالمعنى (متجهات):** البحث في المستندات لفظي مرتب بـ BM25 مع توحيد الكلمات العربية، فلا يطابق المرادفات. البحث بالمعنى يحتاج مزوّد تضمينات (embeddings) غير متوفر في المنصة بعد.
- **المستندات الممسوحة ضوئياً:** لا يوجد تعرّف ضوئي على الحروف (OCR)، فملف PDF المصوّر يظهر «بلا نص». وبعض العناوين في ملفات PDF قد تُستخرج حروفها مبعثرة إذا رُسمت حرفاً حرفاً.
