# المرحلة الخامسة: الوكلاء والأتمتة

**معيار القبول:** «يستطيع المستخدم إعداد وكيل، واختباره، ونشره مع صلاحيات وحدود واضحة».
يتحقق منه `tests/test_agents.py`، ومحرك الأتمتة في `tests/test_automation.py`.

## Agent Builder: وكلاء يبنيهم المستخدم

| المكوّن | التنفيذ |
|---|---|
| الهدف والتعليمات | نص التعليمات يُضاف بعد قواعد ثابتة لا يستطيع صاحب الوكيل إلغاءها |
| الأدوات | قائمة مسموح بها (allowlist) من أدوات المنصة |
| الصلاحيات | الوكيل يعمل **بصلاحيات من يشغّله**. الأدوات الفعلية = قائمة الوكيل ∩ صلاحيات المستخدم |
| الميزانية والحدود | حد للخطوات (حتى 8)، وحد تكلفة لكل تشغيل (حتى 2$)، وميزانية شهرية للوكيل، فوق ميزانية المؤسسة |
| الاختبار | حالات اختبار: أدوات يجب أن تُستدعى، وأدوات ممنوعة، ونصوص يجب أن تظهر في الرد |
| النشر | **لا يُنشر إصدار إلا إذا نجحت آخر نتيجة لكل حالة اختبار على هذا الإصدار نفسه** |
| الإصدارات | الإصدار يُجمَّد بمجرد اختباره أو تشغيله، فالتعديل ينشئ مسودة جديدة. الرجوع = نشر إصدار أقدم |
| الإيقاف | مفتاح تشغيل وإيقاف فوري، وسحب أداة فورًا (`disabled_tools`) دون إعادة نشر |
| السجل | كل تشغيل يُسجَّل: المُدخل، الرد، الأدوات وحالاتها، التكلفة، والإصدار |

**ضمانات «لا يمنح نفسه وصولًا»:**
- لا توجد أداة تعدّل وكيلًا أو دورًا أو صلاحية.
- كل تغيير في البيانات يبقى إجراءً ينتظر موافقة المستخدم، كما في المرحلة الثالثة.
- الأداة خارج القائمة تُرفض حتى لو كان المستخدم نفسه يملك صلاحيتها.
- في PostgreSQL: الإصدار المجمّد لا يُعدّل (trigger)، وسجل التشغيل للإضافة فقط.

## محرك الأتمتة (Workflow Engine)

محرك تقليدي يعمل دون ذكاء اصطناعي، ويستطيع تشغيل وكيل كخطوة من خطواته.

```
حدث (يُسجل في outbox داخل نفس معاملة التغيير)
  → كل سير عمل مفعّل على هذا الحدث → تشغيل واحد فقط لكل (سير عمل، حدث)
  → الشروط (كلها) → الإجراءات بالترتيب
       create_task | notify | require_approval | run_agent
  → فشل؟ إعادة محاولة بعد 1 ثم 2 ثم 4 دقائق → بعد 3 محاولات: failed + إشعار لصاحب سير العمل
```

| عنصر المخطط | التنفيذ |
|---|---|
| Trigger | 14 حدثًا: إنشاء عميل، إنشاء/ترحيل/دفع/إلغاء فاتورة، **تأخر فاتورة** (فحص يومي، مرة واحدة لكل فاتورة)، عرض سعر/تأكيد/تسليم، استلام/جرد مخزون، إصدار/نشر تطبيق، فشل وكيل |
| Conditions | `eq ne gt gte lt lte contains in exists` على حقول الحدث، والمقارنة الرقمية للمبالغ دقيقة (Decimal) |
| Actions | مهمة (لشخص، أو لمن سبّب الحدث، أو لدور كامل)، إشعار، موافقة، تشغيل وكيل منشور |
| Approvals | خطوة توقف التشغيل حتى يوافق من يملك الصلاحية المحددة. قائمة «موافقاتي» لكل مستخدم |
| Retries | تراجع أُسّي، والخطوات الناجحة لا تُعاد |
| Failure Handling | بعد 3 محاولات: حالة failed، وإشعار لصاحب سير العمل |
| Audit Trail | كل تشغيل وكل خطوة ونتيجتها، وقرارات الموافقة باسم من اتخذها |

**منع التكرار (المطلب الصريح في المخطط):**
- لكل (سير عمل، حدث) تشغيل واحد فقط، بقيد unique في قاعدة البيانات.
- كل تشغيل يُعالج في معاملة مستقلة: الإجراء وسجل خطوته يُحفظان معًا أو يُلغيان معًا. لا نصف تشغيل.
- المهام والإشعارات تحمل مفتاح منع تكرار (`wf:{run}:{step}`).
- الاختبار يثبت أن معالجة الأحداث مرتين لا تنشئ مهمة أو إشعارًا ثانيًا، وأن خطوة ناجحة سبقت خطوة فاشلة لا تتكرر مع إعادة المحاولة.

**أمان المحرك:**
- **القوالب:** `{{field}}` بحث فقط، ولا تنفيذ لأي كود.
- **منع الحلقات:** سير عمل يُطلقه «فشل وكيل» لا يستطيع تشغيل وكيل.
- **صلاحيات خطوة run_agent:** تعمل بصلاحيات صاحب سير العمل **الحالية**. إن لم يعد عضوًا تفشل الخطوة.
- **عدم تراكم الأحداث:** الأحداث تُسجَّل فقط إذا وُجد سير عمل يستمع لها.
- **سير العمل لا يرى إلا مؤسسته:** العامل (worker) يعالج كل مؤسسة في جلسة مربوطة بها. في PostgreSQL يعرف المؤسسات من دالة تعيد المعرّفات فقط، وRLS يعمل كالمعتاد.

## التشغيل

```bash
python -m novara.worker            # حلقة مستمرة كل 30 ثانية
python -m novara.worker --once     # مرة واحدة (cron مثلًا)
```

أو من الـ API لمؤسسة واحدة: `POST /orgs/{org}/automation/process`.

## ما لم يُنجز بعد

- **Webhooks للأنظمة الخارجية:** تحتاج حماية من SSRF، وتوقيع، وإعادة محاولة. لم أضفها كإجراء بعد.
- **معرفة الوكيل وذاكرته** (ملفات مرجعية، RAG) بصلاحيات المستخدم.
- **منشئ سير عمل مرئي في الواجهة.**
- **مشغّلات مجدولة عامة** (كل يوم أحد مثلًا). الموجود حاليًا فحص التأخر اليومي فقط.
- **تقييم الوكلاء بالنموذج الحقيقي:** حالات الاختبار تعمل مع Claude فعلًا عند توفر مفتاح، لكن الاختبارات هنا بنموذج مبرمج مسبقًا.
